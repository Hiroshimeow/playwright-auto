2. **Reload-first** if CDPA is down, stale, source-drifted or deadlocked: stop only the affected CDPA task if a safe official Stop is eligible; invoke the existing `workflows/self-repair/reload_cdpa.ps1` for API/dashboard/worker. Preserve Chrome 9202/9212, accepted-Send records and other tabs. If reload is already in progress, reconcile it on the next check rather than launching an overlapping reload.
3. If a Solo is still legitimately RUNNING, inspect it and make one narrow root-cause fix if independently reproduced; do not create a second owner. For PAUSED/BLOCKED, reconcile command/control/receipt before a single safe Resume. For STOPPED, require official applied Stop and CLEARED cleanup; do not replay old accepted request. Never invent PASS.
4. Continue the **smallest unfinished gate** with the existing G6 owner/workflow. Favor actual local code/test fixes over repeated prose. Respect dirty worktree, require failing-first tests for any code fix, and recheck model High/Extra High per newly owned browser task.
5. Update checklist checkboxes only after evidence is verified, and write concise proof to `PROGRESS.md` or an exact receipt (task ID, tests, command exits, evidence, files changed, next action). Report the gate advanced, root cause, remaining blocker and release verdict.
6. For an already-owned task with one actionable MCP Allow button, use the **existing auto-Allow once** path even if UI labels the prompt `Suspicious Instruction`; do not add a label-based gate, duplicate-click, or request manual approval for this known operation. If the actual task identity/Allow surface is ambiguous, the accepted Send ledger is uncertain, or an unrelated permission cannot be handled safely, record the concrete blocker without guessing or replaying.
7. Only request shutdown/disable the recurring ChatGPT automation when all G0–G9 are checked PASS and a final release verdict is independently validated.
