# Freelancer bid memory palace

Offline, UTF-8 learning files for `@duonghcu` (Japan, written-only). Start with [INTEGRATION.md](INTEGRATION.md) for the operator loop. Python 3.11+; no runtime dependencies. Run `python -B -X utf8 bid_memory.py --help` or append `COMMAND --help`. The default root is the script directory; `--root ABSOLUTE_PATH` **before** the command can point to another complete copy for tests. No network, browser, or credentials are used.

| Room | What it owns |
| --- | --- |
| `tactics/` | One JSON card per tactic, with dated rule, class scope and cited evidence entries. `recall` counts `support`, `counter` and `guidance` from those entries rather than maintaining a second tally. These counts are observations, not bids. |
| `job_classes/` | One class card (title, aliases, pricing notes). Current bids/replies/awards live in the ledger and are projected per class through `recall --class` and `stats`; never hand-maintain totals in cards. |
| `clients/` | Observed screening method and qualitative patterns, good signs, and red flags. No customer PII. |
| `language/` | EN/VI phrasing, opening and negotiation examples, and the evidence register for reply-linked openings. Examples are untested; none is claimed as a verified winner. |
| `failures/` | Reusable root-cause notes and links to historical attempt IDs where identified. Attempt-specific failures are in the ledger; `recall --failures [KEYWORD]` lists them with root causes, including resolved incidents. |
| `outcomes/` | One immutable JSON snapshot per attempt (`<attempt-id>.json`, including one per confirmed bid). Only `outcomes/updates/<event-id>.json` receives later observations; updates are patches, not new bids. |

## Data and interpretation

- `amount` and `market_average` are numbers in the same `currency` and `basis` (`fixed` or `hourly`). `duration_days` is the **delivery** estimate for a fixed quote, never listing age; `weekly_limit` is hours/week for hourly quotes. `age_minutes` is listing age at bid; `bid_count` is other bids then. Quote, market snapshot, client flags, and `bid_at` remain as originally recorded. Missing facts are JSON `null`; no tactic tag means there is no documented usage. `recorded_at` is the local write time in UTC, not the date bid. `last_updated` for tactics is a JST date.
- The latest revision number wins for fields changed by an update, independent of filename/timestamp order. A missing field preserves the prior value; `--replied unknown` explicitly restores unknown. Updates can attach a first verified `bid_id` to an ambiguous attempt; they cannot swap it or change the snapshot. Additional verified context can be cited in an updated lesson. `--event-id` is required for updates only. Identical replay of a command is idempotent; conflicting reuse exits nonzero. The shared writer lock plus same-directory atomic publication keeps cooperating writes serialized; keep one writable palace on a local filesystem.
- The denominator is distinct verified bid IDs, including the one frozen unawarded, **not** failed/blocked/ambiguous or screened-out attempts. Numerators are verified substantive replies and accepted funded awards, independently. Percentages are confirmed results to date divided by all verified submissions; if outcomes are missing these are **lower bounds**, not final conversion rates. `reply_unknown` and `award_unresolved` expose coverage. A zero denominator is `n/a` or `null` in JSON. Each bid can count for several actual tactic tags; do not add tactic rows to get an overall total. Research and prose evidence do not create tactic impressions.
- To add a class, add a UTF-8 `job_classes/<slug>.json` with `title`, `aliases` (list of strings) and `pricing_notes`. To add a tactic use `lesson ID --title TITLE --rule RULE --evidence-id ID --kind guidance --evidence NOTE --source REF`; repeat `--class` to restrict its scope. Without `--title`, `--rule`, or a scope flag, an update retains those fields. Reuse evidence IDs only for identical entries. Use `--general` to clear class scope. Preserve meaningful variant IDs for comparisons.
- Append reply-linked wording to `language/openings-evidence.json` under `verified_openings`: each entry has `locale` (`en` or `vi`), `bid_id`, `opening` (redacted) and `source` (receipt/event reference). Recall shows the last five appended entries; the full register stays in the file.
- Seed provenance: 10 operator-verified platform bids, 2 ambiguous executor observations for one project, 3 local pre-boundary blocked evaluations and 1 local not-submitted decision. Form incidents without reliable project IDs/counts are pattern cards, not fabricated ledger rows. The bid playbook and 48-hour research artifacts were not available in this checkout; the playbook summary and local reports are cited in the seed files.
